# 补给工具与闭环设计草案

## 当前工具

`python3 tools/bot_supply.py restock dev/NAME` 默认只读预览；`--apply --max-cost 5000 --max-count 1000` 明确执行，金额和购买数量分别为本次总上限。执行前必须由操作者确认脚本已停止、角色处于安全位置、商店及路线可用。可重复指定 `--sell-etc 物品ID`，先出售人工确认的 etc，已知保护物品仍会排除；不指定则不出售，绝不自动卖装备。现有保护名单不是完整任务物品数据库，操作者须核对指定物品用途。商店报价及金币读取不可用、商品不可购买、余额或上限不足、交易失败或补货后仍有缺口时停止；可能已发生部分交易，不可盲目重放。商店关闭后停留现场，不自动返回。商店商品、价格和箭矢支持以实际 GUI 为准；单次交易数量上限 1000。

## 尚未实现的自动闭环

拟议状态机：HUNT → LOW（发出包含低库存原因的 `supply/low`，停止攻击与移动，等待脚本终态和放键）→ SAFE_TRAVEL（仅走已验证的安全城镇路线）→ RESTOCK（实际商店卖 etc、按预算采购并核对库存）→ RETURN（使用 #418 提供的 `plan.conf` 狩猎地图及路线接口）→ HUNT。任何状态观察失败、停手未确认、无安全路线、商店未售目标、余额不足或交易结果不明进入 STOPPED 并报告，禁止自动恢复及重复交易。城镇不可达时原地停手，不假设当前位置安全。

阈值拟从角色的独立 `supply.conf` 读取红药、蓝药、箭矢低水位；缺项、未知库存或配置错误应停手并报告，职业无箭矢目标时不触发箭矢告警。补货目标仍由工具现有等级和职业表决定，低水位不得与补足目标混淆。最终配置合同与 #418 合并后的回图接口需要集成时确定；现阶段没有自动监听事件、自动停手或回图能力。

## 待真实验证

由维护者在 dev GUI 验证商店读取、卖出保护、箭矢和药水购买、预算不足及失败停留；live 仅按正常游玩授权验证。实际补货必须先停掉活动 Lua，GUI 商店交易与 #418 回图均需现场确认，离线测试不能替代游戏验收。
