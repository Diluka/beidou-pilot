# 按影响验证

- Python/测试/导出接线：运行 `mem:suggested_commands` 中的unittest入口；目录迁移还要确认导出副本能用同一入口运行。真实客户端试用按AGENTS.md中的客户端运行行为影响判断适用范围。
- Dockerfile/原生构建：容器内完整构建，核对实际镜像身份/入口/资源外置；游戏就绪以启动日志和只读 API 为准。
- harness/ai入口/技能打包：核对 docs/CI.md 的既有无认证模型合同。旁路运行边界在 headless/GUI 验证无 LLM 时原生脚本持续、LLM 退出重接后同 script.id 继续、重接只观察并无新执行；显式脚本取消放键与客户端关闭分别验证。模型质量、token、时延和询问按相关需求另验；见 docs/HARNESS.md。
- 控制行为：默认在常驻服复用授权已有账号角色与就绪实例，确认实际动作、取消放键、必要的存档/重开；新账号或角色仅在场景必须时创建，隔离服仅限常驻服无法安全验证等特殊情况并记录原因。IPC桩覆盖协议边界；GUI原语与无头能力分别判断。
- 按AGENTS.md选择简易或完整交付流程；纯文档使用简易流程，代码与构建改动核对docs/CI.md中的常规检查，并按影响判断真实客户端试用范围。CI不配置为远端强制门禁；CI 通过以远端结果为准。
- 收尾只回收本轮资源，保留既有改动；检查git diff --check与子模块工作树。用户选定并授权推进需求后，按AGENTS.md自主提交/推送、建PR、验收与合并；入池不自动启动开发。
- 稳定约定变化时纠正相关记忆并运行serena memories check；临时任务过程/凭据/运行数据不写入记忆。
