# 共享 Lua 策略维护约定

## 当前定位

这里是初步脚手架策略，用于跑通状态判断与动作编排。已有阈值、等待时间、目标选择、移动和恢复流程可能不符合真实游戏情况；目录分类或测试通过不代表策略成熟，也不构成冻结现有实现的理由。

后续根据实际客户端行为、失败场景和业务目标持续迭代。按本次目标核对相关的位置、HP/MP、库存、经验、释放与实际效果；不要把派发成功、脚本返回或测试桩响应当成游戏效果。先区分策略参数、时序差异与已确认的原生错误：参数可用有界试验调整，确认的原生错误从源头修复。其他已支持路径可继续使用，替代路径的成功不代表该缺陷修复通过。

## API 文档入口

写脚本先读 [docs/LUA_API.md](../../docs/LUA_API.md)，使用其中声明的状态、动作、返回值和错误语义。常规脚本编写不需要逐次阅读 C++ 绑定；遇到文档未覆盖或行为不符时再查实现，核实后补齐文档。

公共 Lua API 有新增、删除或语义变化时，同步更新这份 API 文档，不能只改实现或在记忆中补充口头约定。Serena 只保存入口和易误改约束，不复制另一份 API 全集。

## 职责边界

- 基础操作由统一 `game` API 提供；两端脚本契约以 headless 接口为基准，各端原生适配器实现必要差异。这里不新增只转发一个基础操作的脚本，也不保留旧接口兼容壳。
- `travel/`、`combat/`、`recovery/` 保存现有复合能力。业务参数由调用方传入；公共运行时负责执行期限、取消及放键，策略只决定如何使用动作和预算。
- `travel/_common.lua` 只放当前旅行策略实际复用的检查和对齐逻辑，不作为操作入口。其他通用函数有真实复用再提取。
- `examples/` 仅用于演示，不由正式策略自动加载。固定角色、地图或验收流程不混入正式策略；验收脚本放测试目录。
- 未知状态保持未知，不将缺失库存、目标或效果当作空、零或成功。未知只阻断依赖该事实的操作，不让无关未知阻断整个流程。计划的动作要核对场景和角色身份，避免旧规划作用于新实例。
- 新能力实际开发时再增加文件；不预建通用寻路、自动收集等空目录、占位脚本或泛化框架。

## 迭代与验证

只保留能说明公共契约、实际失败或效果确认的必要测试，不为固定当前调参结果堆叠断言。通过条件以到达、交互、拾取等实际目标为准，精度只取业务所需；两端一致性按已声明的语义判断，不要求逐像素轨迹或精确墙钟时长相同。位置偏移、随机掉落、伤害、时序等优先采用有界真实冒烟和采样；保留失败与未覆盖事实，再按影响范围回归。不要为让旧用例通过而保留已无实际价值的策略分支。整体调试与验收边界见[项目约定](../../AGENTS.md#验收方式)。
