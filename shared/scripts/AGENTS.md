# 共享 Lua 策略维护约定

## 当前定位

这里是初步脚手架策略，用于跑通状态判断与动作编排。已有阈值、等待时间、目标选择、移动和恢复流程会按真实游戏情况持续调整；目录分类与测试结果作为当前状态的记录。

后续根据实际客户端行为、失败场景和业务目标持续迭代。按本次目标核对相关的位置、HP/MP、库存、经验、释放与实际效果；派发成功、脚本返回和测试桩响应作为过程证据。先区分策略参数、时序差异与已确认的原生错误：参数可用有界试验调整，确认的原生错误从源头修复。其他已支持路径可继续使用，缺陷的修复以源头修复后的验证为准。

## API 文档入口

写脚本先读 [docs/LUA_API.md](../../docs/LUA_API.md)，使用其中声明的状态、动作、返回值和错误语义。常规脚本编写不需要逐次阅读 C++ 绑定；遇到文档未覆盖或行为不符时再查实现，核实后补齐文档。

公共 Lua API 有新增、删除或语义变化时，同步更新这份 API 文档；实现、文档与记忆保持一致。Serena 只保存入口和易误改约束，不复制另一份 API 全集。

## 职责边界

- 基础操作由统一 `game` API 提供；两端脚本契约以 headless 接口为基准，各端原生适配器实现必要差异。复合能力直接调用 `game` API。
- `travel/`、`combat/`、`recovery/` 保存现有复合能力。业务参数由调用方传入；公共运行时负责执行期限、取消及放键，策略只决定如何使用动作和预算。
- `travel/_common.lua` 只放当前旅行策略实际复用的检查和对齐逻辑。其他通用函数在有真实复用后提取。
- `travel/_terrain.lua` 是 `walk_to` 与 `hunt` 共用的单地图平台图与最短路径搜索：竖直墙切分、绳索连接和边代价只在这里维护，消费者只执行动作并核对结果。
- `examples/` 仅用于演示，由调用方显式加载。固定角色、地图或验收流程写在测试目录；正式策略只保留可复用逻辑。
- 未知状态保持未知，缺失库存、目标或效果按未知值处理。未知只阻断依赖该事实的操作，无关未知不影响整个流程。计划的动作要核对场景和角色身份，新实例重新规划。
- 新能力实际开发时再增加文件；通用寻路、自动收集等能力在实现时创建对应文件。

## 迭代与验证

只保留能说明公共契约、实际失败或效果确认的必要测试。通过条件以到达、交互、拾取等实际目标为准，精度只取业务所需；两端一致性按已声明的语义判断，轨迹与墙钟时长按业务所需精度核对。位置偏移、随机掉落、伤害、时序等优先采用有界真实冒烟和采样；保留失败与未覆盖事实，再按影响范围回归。旧用例对应的策略分支按实际价值整理。整体调试与验收边界见[项目约定](../../AGENTS.md#验收方式)。
