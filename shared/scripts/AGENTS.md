# 共享 Lua 示例维护约定

## 当前定位

本目录只保存随镜像固定的 tick 示例，用于演示 `main(context)`、`context.state` 跨调用状态、只读领域观察和 `player` 动作槽。旧的内置策略及函数库已移除，不再维护兼容入口。

示例不是正式策略：不承诺寻路、选怪、命中、精确出手或完整玩法流程。真实策略写在用户工作台的 `/work/scripts` 中，由调用方通过 `script run/start` 显式提交。示例按真实游戏事实推进，动作受理、输入释放和游戏效果分别判断。

## API 文档入口

写脚本查 [Tick Lua API](../../docs/LUA_TICK_API.md)：入口、`@tick.*` 配置、上下文、只读领域、运动观察和动作槽语义都在该页维护。控制、取消与放键规则查[控制协议](../../docs/CONTROL.md)。公共 API 有新增、删除或语义变化时同步更新 tick 文档；Serena 只保存入口和易误改约束，不复制另一份 API 全集。

## 职责边界

- `examples/` 只做演示，由调用方显式加载；固定角色、地图或验收流程写在测试目录。
- 示例使用 tick 引擎的只读领域和 `context.game.player` 动作槽，不使用阻塞动作、`game.sleep()`、任务控制或旧按键接口。
- 方向和动作意图只设置一次，由原生消费者保持；脚本结束时由 Runtime 确认停止所属持续输入并放键，示例不轮询内部握手。
- 未知状态保持未知，缺失库存、目标或效果按未知值处理。未知只阻断依赖该事实的操作，无关未知不影响整个流程。计划的动作要核对场景和角色身份，换图或场景代次变化后重新读取。
- 需要新示例时按真实能力增加文件，不恢复已退役的引擎或函数库。

## 迭代与验证

只保留能说明公共契约、实际失败或效果确认的必要示例与测试。通过条件以实际游戏结果为准，精度只取业务所需；位置偏移、随机掉落、伤害、时序等优先采用有界真实冒烟和采样。保留失败与未覆盖事实，再按影响范围回归。整体调试与验收边界见[项目约定](../../AGENTS.md#验收方式)。
