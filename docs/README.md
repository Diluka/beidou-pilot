# 文档索引

本目录按“它现在是什么”分层，避免把设计、研究记录和当前契约混在一起。阅读或改文档时先确认类别：

| 类别 | 含义 | 是否代表当前能力 |
| --- | --- | --- |
| 产品与使用 | 项目定位、上手、操作流程 | 是 |
| 接口契约 | CLI、tick Lua、控制协议、架构边界 | 是；以当前实现为准 |
| 设计与路线 | 尚未交付的应用层、阶段计划 | 否；是计划，不是承诺 |
| 研究记录 | 原版行为调查、校准证据、历史验证 | 否；是证据，不是产品契约 |
| 维护流程 | 开发约定、CI、依赖、格式、Issue 标签 | 流程说明 |

## 维护规则

- 当前能力写在“产品与使用/接口契约”；计划写在“设计与路线”；调查和一次性验证写在“研究记录”。不要把三者混写。
- 旧 Issue/PR 是当时记录，不是当前路线图；需要保留的结论应整理进上述分层文档，而不是让读者从历史讨论里推断现状。
- 新增公开接口时同步更新对应契约文档；只改实现不改文档视为未完成。
- 研究记录可以保留历史证据链接，但要明确日期、版本和适用范围；证据目录被清理时改为“所属环境保留”，不留下失效的本地路径。
