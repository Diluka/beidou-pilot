# 客户端能力

本页按使用场景列出客户端当前能做什么、从哪里进入。具体命令、字段和错误见 [CLI](CLI.md)、[Tick Lua API](LUA_TICK_API.md) 和 [控制协议](CONTROL.md)。

## 定位

客户端提供两件事：通过 CLI 观察游戏状态，通过 tick Lua 提交角色动作。操作者用 CLI 发起脚本、读取状态并核对游戏结果；持续动作由客户端更新线程里的 tick 引擎执行。伴游机器人建立在这套能力之上，设计与阶段见 [伴游机器人设计与路线](COMPANION_BOT.md)。

## 动作与控制

- **动作入口**：移动、跳跃、普攻、技能、拾取、用药都从 tick Lua 的 `context.game.player` 提交。调用返回本 tick 意图受理；命中、消耗、恢复和拾取结果从游戏状态核对。
- **一次性请求**：正常复活用 `revive` 或 `player.revive()`；AP 自动分配用 `auto-ap` 或 `player.auto_ap(...)`。请求发出后观察同一角色的 HP、AP 和属性，不重复提交。
- **单动作槽**：同一客户端的所有 tick 会话共享一个 `player`，按接纳顺序后写覆盖。需要外部控制时，写 `/work/bot/queue` 文件或启动专用会话，由单一控制者提交动作。
- **伴游机器人后端**：bot 主包依赖 POSIX shell 与文件邮箱，仅支持 POSIX headless；GUI/Wine 后端明确拒绝启动队列 IO。
- **策略位置**：客户端不内置寻路、狩猎、战斗、跟随或组队任务策略。策略写在角色工作台的 tick Lua 或伴游机器人应用中；`shared/scripts/` 只放随镜像固定的示例和校准探针。
- **长时运行**：`script start ... --continuous` 没有总期限。断线会退出客户端进程；脚本结束或取消后客户端继续运行。长期运行需要外部监督、事件日志轮转和定期关闭重开。

## 观察

- **角色、场景、背包、任务**：两端通过各自原生观察提供，核心字段见 [Tick Lua API](LUA_TICK_API.md#独立只读领域)。读取时检查领域 `status`；缺失字段为 `nil`。
- **同图其他玩家**：`game.scene.players` 提供引用、角色 ID、名字、等级、位置、速度和朝向；引用对当前场景代次有效。用这些字段跟随同图玩家。
- **怪物 HP**：headless 提供 `hp_percent`；GUI 不提供该字段。需要伤害进展时优先用 headless 脚本，或从怪物消失、经验变化核对。
- **聊天与队伍**：当前 `game.chat` 为 `unsupported`，没有消息读取/发送，也没有队伍成员、队员 HP、队友地图领域。玩家私聊指令、机器人回复和组队观察需要新增原生能力。
- **交互**：`game.dialog/shop/ui/interaction/notifications` 提供只读观察。GUI 的对话、商店、背包换装和通知响应由 CLI/GUI 原生路径执行；headless CLI 支持当前 NPC 与对话控件引用，任务列表、接取和交付尚未交付，tick Lua 暂无激活入口；没有观察到服务端后续页或结束信号时会保守等待，后续交互会被阻塞。活动 Lua 期间交互输入返回 `input_busy`。
- **静态资料**：名称、物品恢复属性、NPC 范围和地图地形来自配置的原版 IMG，经共享解析库读取。静态资料用于查询和规划；现场对象与结果从当前客户端观察。

## 导航与跨图

- **同图导航**：`context.scene.terrain.navigation` 提供平台、墙、绳和几何候选关系；边代价、筛选、最短路和执行由脚本维护。客户端不内置 A*、跟随或跨平台执行器。
- **跨图路线**：`world-map route START GOAL` 是只读 CLI 查询，返回有向门户腿序列。普通 `script run/start` 不注入 `context.route`，运行中的 Lua 也不能查询路线；需要跨图时由调用方查询路线并通过 `workbench.json`/脚本参数注入，或把路线规划放到新的运行时能力里。
- **运动分支**：台阶、绳梯、落下、移动平台、游泳/飞行在两端有覆盖差异。复杂地图先用真实客户端跑一段短脚本核对落点和路径，再扩大范围。

## 养成与维护

- **AP**：`auto-ap`/`player.auto_ap` 按原生自动分配规则处理全部剩余 AP。客户端不提供手动逐点 AP 分配；使用自动分配前核对角色属性和剩余 AP。
- **SP**：`skill-up` 逐点分配并核对技能等级和剩余 SP，要求当前没有活动脚本。当前目标是冒险家职业群及指定的初学者技能；其他职业群按 `skill-up` 当次返回的能力范围判断。
- **装备、商店、特殊对话**：由 GUI CLI 或原生 GUI 路径提供；headless 暂不支持装备、商店及未知类型的对话控件。活动 Lua 期间交互操作返回 `input_busy`，养成按“停手 → 释放控制 → 维护操作 → 重新启动”的顺序完成。
- **不可逆操作**：转职、洗点、大额交易和奖励领取先写明确计划并核对现场；客户端提供动作和观察，决定由操作者作出。

## 跨客户端观察基线

同一个角色在两个客户端里的表现可能不一致：本端观察自己的位置/速度正常，另一端的观察端却看到悬空、原地走路或位置跳变。移动/动作类任务验收需要跨客户端核对，工具与用法见 [`tools/observer/README.md`](../tools/observer/README.md)。

2026-11-25 live 双端对录（headless + 原版 GUI，地图 10000）的基线偏差：

- headless 入图后静止时观察端位置差约 60px（服务端进入场地广播 y-42），首次移动出现 42px+18px 的位置跳变；停止后 GUI 观察端保留约 -123px/s 残留速度和 1.35–2.29s 位置尾巴，最终位置差 6–9px。见 #371。
- headless 移动包缺少 fieldKey，服务端启用校验后会静默丢弃移动包。见 #372。
- headless 观察远端玩家时速度按 8ms 间隔计算、数值放大约 3.75 倍。见 #379。

## 尚未提供

伴游机器人需要、当前客户端还没有的入口：

| 能力 | 用途 | 当前替代 |
| --- | --- | --- |
| 私聊/队伍聊天收发 | 玩家指令、机器人回复、自然语言入口 | 文件邮箱 `/work/bot/queue` |
| 队伍邀请/接受与成员观察 | 组队、跟随、队员状态 | 同图 `scene.players` 观察 |
| headless 任务列表、接取、交付及商店 | 任务、补给 | 普通 NPC 对话可用 CLI 引用交互；任务与商店使用 GUI |
| 运行时路线查询/注入 | 跨图跟随、自主旅行 | `world-map route` + 启动前注入 |
| 玩家交易 | 部分经典组队任务的通行证转移 | 由玩家在 GUI 完成 |
| 手动 AP 分配 | 按计划逐点养成 | `auto-ap` 或 GUI 操作 |

详细契约和阶段见 [伴游机器人设计与路线](COMPANION_BOT.md)。交付时按客户端真实结果和对应验收更新本页。
