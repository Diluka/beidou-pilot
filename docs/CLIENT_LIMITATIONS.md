# 客户端能力

本页按使用场景列出客户端当前能做什么、从哪里进入。具体命令、字段和错误见 [CLI](CLI.md)、[Tick Lua API](LUA_TICK_API.md) 和 [控制协议](CONTROL.md)。

> 原生 headless 客户端已于 2026-11-27 退役；本页只描述原版 GUI 后端。旧的跨端差异记录保留在[远端玩家验证](REMOTE_PLAYER_VALIDATION.md)，不再作为当前能力。

## 定位

客户端提供两件事：通过 CLI 观察游戏状态，通过 tick Lua 提交角色动作。操作者用 CLI 发起脚本、读取状态并核对游戏结果；持续动作由客户端更新线程里的 tick 引擎执行。伴游机器人建立在这套能力之上，设计与阶段见 [伴游机器人设计与路线](COMPANION_BOT.md)。

## 动作与控制

- **动作入口**：移动、跳跃、普攻、技能、拾取、用药都从 tick Lua 的 `context.game.player` 提交。调用返回本 tick 意图受理；命中、消耗、恢复和拾取结果从游戏状态核对。
- **一次性请求**：正常复活用 `revive` 或 `player.revive()`；AP 自动分配用 `auto-ap` 或 `player.auto_ap(...)`。请求发出后观察同一角色的 HP、AP 和属性，不重复提交。
- **单动作槽**：同一客户端的所有 tick 会话共享一个 `player`，按接纳顺序后写覆盖。需要外部控制时，写 `/work/bot/queue` 文件或启动专用会话，由单一控制者提交动作。
- **伴游机器人后端**：bot 主包通过纯 Lua 固定槽位文件邮箱在 GUI/Wine 运行；命令协议与状态写入限制见 [机器人手册](../bot/README.md)。
- **策略位置**：客户端不内置寻路、狩猎、战斗、跟随或组队任务策略。策略写在角色工作台的 tick Lua 或伴游机器人应用中；`shared/scripts/` 只放随镜像固定的示例和校准探针。
- **长时运行**：`script start ... --continuous` 没有总期限。断线会退出客户端进程；脚本结束或取消后客户端继续运行。长期运行需要外部监督、事件日志轮转和定期关闭重开。

## 伴游机器人：当前能力和限制

当前主包具备平台巡逻、绳梯和水平跳、顺路拾取、掉层恢复、低补给停手与地图绑定回图；`idle`/`hunt` 在绑定地图之外会尝试已有普通门户路线。行为和配置见 [机器人手册](../bot/README.md)。这些能力不是所有地图的可达性或长时稳定性保证。

- **城镇与商店导航**：门户或 NPC 路线曾出现 `landing_mismatch`，影响回图和补货；遮挡类修复仍在草稿中，水平距离问题尚未解决（[#429](https://github.com/Diluka/beidou-pilot/issues/429)、[PR #438](https://github.com/Diluka/beidou-pilot/pull/438)）。
- **NPC/商店后的输入**：现场曾在交互后出现移动和跳跃无效，即便会话已结束且按键已释放；当次以工作台 `close` 后 `open` 恢复。操作后核对实际位移，出现冻结时采用此已观察 workaround，原因仍待确认（[#440](https://github.com/Diluka/beidou-pilot/issues/440)）。
- **补给**：低水位可停手，但低补给→回城→购买→回图→恢复狩猎的无人值守闭环尚未完成；白名单编排 [PR #433](https://github.com/Diluka/beidou-pilot/pull/433) 是草稿（[#419](https://github.com/Diluka/beidou-pilot/issues/419)）。
- **远程攻击**：跨平台驻留选怪使用几何近似，弹道与实际命中尚待真机核对（[#425](https://github.com/Diluka/beidou-pilot/issues/425)）。大图 hunt 曾因单 tick 超预算取消；文件 IO 优化已合入，根因仍未定位（[#423](https://github.com/Diluka/beidou-pilot/issues/423)）。
- **常驻服操作**：仅按既有授权和角色计划正常游玩，不使用 GM 写入、直接数据库修改或开发服准备操作。观察脚本终态、输入释放和实际效果；交互后如发生上述冻结，关闭并重开所属客户端。

## 观察

- **角色、场景、背包、任务**：通过原版客户端原生观察提供，核心字段见 [Tick Lua API](LUA_TICK_API.md#独立只读领域)。读取时检查领域 `status`；缺失字段为 `nil`。
- **同图其他玩家**：`game.scene.players` 提供引用、角色 ID、名字、等级、位置、速度和朝向；引用对当前场景代次有效。用这些字段跟随同图玩家。
- **怪物 HP**：当前不提供 `hp_percent`；需要伤害进展时从怪物消失、经验变化核对。
- **怪物控制权**：不提供 `controlled` 标记；按原版客户端的实际行为处理。
- **聊天与队伍**：`game.chat` 仍为 `unsupported`，tick Lua 和 CLI 没有聊天收发入口，也没有队伍成员、队员 HP、队友地图领域。原版 GUI 桥在原生层提供以下能力，不依赖 UI 或键位：收到悄悄话位置询问时用悄悄话回复当前地图名；解析 `@` 开头的私聊指令（位置/状态/帮助/跟随/打猎/停下/停止），动作类指令只接受配置的 owner，写入 bot 邮箱交给 tick 控制器执行；伴游机器人策略模式变化时广播，处于队伍中发组队频道，否则对所有人广播；读取桥目录的 `party-cmd.txt` 执行组队创建/邀请/接受/拒绝/退出。桥从组队包跟踪队伍状态，不向 Lua 暴露队伍成员。
- **交互**：`game.dialog/shop/ui/interaction/notifications` 提供只读观察。对话、商店、背包换装和通知响应由 CLI/GUI 原生路径执行；没有观察到服务端后续页或结束信号时会保守等待。活动 Lua 期间交互输入返回 `input_busy`。
- **静态资料**：名称、物品恢复属性、NPC 范围和地图地形来自配置的原版 IMG，经共享解析库读取。静态资料用于查询和规划；现场对象与结果从当前客户端观察。

## 导航与跨图

- **同图导航**：`context.scene.terrain.navigation` 提供平台、墙、绳和几何候选关系；边代价、筛选、最短路和执行由脚本维护。客户端不内置 A*、跟随或跨平台执行器。
- **跨图路线**：`world-map route START GOAL` 是只读 CLI 查询，返回有向门户腿序列。普通 `script run/start` 不注入 `context.route`，运行中的 Lua 也不能查询路线；需要跨图时由调用方查询路线并通过 `workbench.json`/脚本参数注入，或把路线规划放到新的运行时能力里。
- **运动分支**：复杂地图先用真实客户端跑一段短脚本核对落点和路径，再扩大范围。

## 养成与维护

- **AP**：`auto-ap`/`player.auto_ap` 按原生自动分配规则处理全部剩余 AP。客户端不提供手动逐点 AP 分配；使用自动分配前核对角色属性和剩余 AP。
- **SP**：`skill-up` 逐点分配并核对技能等级和剩余 SP，要求当前没有活动脚本。当前目标是冒险家职业群及指定的初学者技能；其他职业群按 `skill-up` 当次返回的能力范围判断。
- **装备、商店、特殊对话**：由 GUI CLI 或原生 GUI 路径提供。活动 Lua 期间交互操作返回 `input_busy`，养成按“停手 → 释放控制 → 维护操作 → 重新启动”的顺序完成。
- **不可逆操作**：转职、洗点、大额交易和奖励领取先写明确计划并核对现场；客户端提供动作和观察，决定由操作者作出。

## 尚未提供

伴游机器人需要、当前客户端还没有的入口：

| 能力 | 用途 | 当前替代 |
| --- | --- | --- |
| 私聊/队伍聊天收发 | 玩家指令、机器人回复、自然语言入口 | 文件邮箱 `/work/bot/queue` |
| 队伍邀请/接受与成员观察 | 组队、跟随、队员状态 | 同图 `scene.players` 观察 |
| 运行时路线查询/注入 | 跨图跟随、自主旅行 | `world-map route` + 启动前注入 |
| 玩家交易 | 部分经典组队任务的通行证转移 | 由玩家在 GUI 完成 |
| 手动 AP 分配 | 按计划逐点养成 | `auto-ap` 或 GUI 操作 |

详细契约和阶段见 [伴游机器人设计与路线](COMPANION_BOT.md)。交付时按客户端真实结果和对应验收更新本页。
