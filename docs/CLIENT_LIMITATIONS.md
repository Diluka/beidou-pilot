# 客户端能力边界与缺口索引

本页说明哪些现有边界会增加 AI 使用 CLI 和 Lua 的成本，并索引已入池的独立用户结果。命令、字段、错误和能力声明仍以 [CLI](CLI.md)、[Lua API](LUA_API.md)、[tick API](LUA_TICK_API.md) 和[架构](ARCHITECTURE.md)为准；Issue 记录最新范围和状态。入池后的功能开发按用户结果逐项启动，简单玩法或外部游戏 AI 接入在此基础上继续推进。

## 当前使用边界

- **动作只由 tick Lua 提交。** 客户端没有 CLI 动作命令，移动、技能、拾取和用药意图写在 UTF-8 tick 文件里，经 `player` 动作槽保持，由原生消费者决定派发。设置返回受理，不表示已施放命中。无内置寻路、狩猎或自动加点策略。
- **领域读取与 GUI 交互分别支持。** tick Lua 以只读领域读取角色、场景、背包、任务和适用 GUI 读数；观察保留来源、支持状态与未知语义。NPC 对话、商店、背包换装、复活和控件激活由原版 GUI 命令提供，无头端只读观察并明确拒绝桌面输入入口。
- **静态资料与现场事实分别核对。** 名称、恢复属性、NPC 范围和地图地形共用配置的原版 IMG 与原生解析库；缺项和未支持值仍明确报告。静态资料可辅助查询、定位与规划，本端实时对象和结果以现场观察为准。
- **后端实现范围不同。** tick 的 `player` 动作槽按本端能力实现，技能首批覆盖战士 1001004/1001005；装备、复活、商店和快捷键是 GUI 路径，无头端返回不支持。动作受理、派发、释放、动画收束与命中/消耗/恢复分别判断，未知保持未知。补齐能力不复制无消费者的图形键盘/快捷栏。
- **热改脚本与更新原生组件成本不同。** tick Lua 文件与活动会话支持在线提交和取消；原生 DLL 或二进制变化仍需要构建并按生命周期重新加载。现有 Docker、工件清单、指纹核验和实例复用继续使用，DLL 热卸载与免重启的原生更新属于独立能力，需要时另行设计。

## 需求索引

下表保留仍可作为独立用户结果跟踪的条目；已随直接动作命令退役的条目不再列出。

| 用户需要的结果 | 当前成本或边界 | 跟踪 |
| --- | --- | --- |
| Lua 直接消费已有领域事实 | tick 只读领域已接入原生观察；保留各端支持、来源及非实时限制 | [#40](https://github.com/Diluka/beidou-pilot/issues/40) |
| 同会话连续完成 GUI 交互与养成 | GUI 命令逐项操作；batch 不承担动态判断 | [#41](https://github.com/Diluka/beidou-pilot/issues/41) |
| 可靠打开可见近距 NPC | GUI 需可核实图形范围与有效目标；无头端只读引用 | [#42](https://github.com/Diluka/beidou-pilot/issues/42) |
| 知道箱子等对象当前是否存在及已知状态 | 原生内部实现已就绪，公开结构化观察待补齐 | [#43](https://github.com/Diluka/beidou-pilot/issues/43) |
| 读取真实动作前提、收束和移动能力 | tick 提供速度、地面、动作锁与参考模型；部分后端仍未覆盖 | [#45](https://github.com/Diluka/beidou-pilot/issues/45) |
| 知道战斗有何原生可核实进展 | 无头提供已收到的服务端目标 HP 百分比；GUI 未知，动作归因仍未知 | [#47](https://github.com/Diluka/beidou-pilot/issues/47) |
| 无头正常对话与接交任务 | 无头端当前无桌面输入入口，任务页只读；GUI 使用控件激活 | [#48](https://github.com/Diluka/beidou-pilot/issues/48) |
| 无头普通商店买卖补给 | 商店流程目前在 GUI 侧完成 | [#49](https://github.com/Diluka/beidou-pilot/issues/49) |
| 实时观察任务变化 | 完整角色包与正常任务增量共同维护；原始进度与关联语义不猜测 | [#52](https://github.com/Diluka/beidou-pilot/issues/52) |
| 无头施放已学职业技能 | tick `player.skill` 支持首批 1001004/1001005；其他类型明确不支持 | [#53](https://github.com/Diluka/beidou-pilot/issues/53) |
| 一次资源准备供查询与规划直接消费 | Catalog 直接查询只读原版 IMG，报告实际来源、指纹和未知版本 | [#55](https://github.com/Diluka/beidou-pilot/issues/55) |
| 减少原生试用准备与版本核对成本 | 现有构建已交付，指定版本复用/装配/核对仍需组织 | [#56](https://github.com/Diluka/beidou-pilot/issues/56) |

同图其他玩家的 `scene.players` 结构化观察两端均已提供（[#57](https://github.com/Diluka/beidou-pilot/issues/57)）：无头端来自原生角色对象，GUI 端来自原版客户端用户池，两端按同一字段口径；HP、装备、队伍关系与 GUI 不可见状态语义不在本观察范围。

## 已有结果与后续验证

在线源码执行已交付（#9）；脚本会话的等待、取消与释放语义由 tick Runtime 统一维护。GUI NPC 同步输入导致的 Lua 调度和释放问题已修复（#33 / PR #35），历史问题从缺失能力清单移除。

后续按独立用户结果选择交付；AI 决策、长期角色路线与记忆保持在客户端外部，持续控制由 Lua 和原生执行。各端仅报告本端真实事实，未知/过期/未支持保留原样，服务端或另一后端的结果另行核对。角色不可逆分配沿已核实计划执行，死亡/复活试验只使用另有明确授权的合适角色。

调试、正式验收和证据复用遵循[开发约定](../AGENTS.md#验收方式)。按实际影响补验对应后端和消费者；纯文档、未变组件和未涉及升级的 PR 按既有证据复用。
