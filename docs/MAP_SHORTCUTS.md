## 待批准的契约和实施设计

1. 原生静态场景按 map/instance/scene_generation 把只读门户原始身份、位置、pt、目标地图及目标名暴露给 Lua；保留缺失值、重复名称及脚本信息，不能静默归并或选第一个。此项涉及共享 C++ 与公开 tick 契约，**本 PR 不实现**。
2. 只有经版本化证据核实的普通同图门户、唯一目标与明确激活方式才能纳入策略，且输入与落点均匹配可站立平台。拒绝跨图、重复名称、脚本、未知类型或不确定坐标；不得仅凭静态 pt 自动标记 verified。
3. Planner 把合格边加入平台图并处理到入口的步行成本；A* 启发必须对低代价传送边仍可采纳，考虑同平台捷径和多个入口。不能只看平台中心或盲目将每条 portal 代价设为零。
4. 执行需先经 mover 走到入口、按已验证方式触发一次、释放输入，以身份及有界位置变化确认到达；超时、意外场景、目标未站稳和取消均停止，不自动重试。必须先验证原生输入消费、换图/同图 scene_generation 的真实语义；跨场景只凭代次不能断言失败或成功。

`bot/lib/shortcut.lua` 是**未连接到主流程的离线概念原型**：合成记录筛选、给出候选边和模拟一次按上确认。`verified` 由测试夹具提供，不是运行时信任机制；原型既不读取 Map.wz，也不构成生产验证白名单。它不改现有 planner/mover，未解决入口步行代价、同平台最短路、生产身份与验证来源。离线测试不能替代真实 GUI 使用；生产接线、原生只读扩展和发布前开发服实测仍待批准和完成。
